# Internationalization (i18n) Architecture & Extension Guide

This document describes the internationalization (i18n) architecture, JSON dictionary management, extension protocols, and automated CI parity checks of the JUMUN platform.

---

## 1. Core Principles

1. **Zero Inline Branching (No Hardcoded Conditions)**:
   - UI code must never contain `if (language === 'ko') ...` logic.
   - All user-facing strings, descriptions, ARIA attributes (`aria-label`), and form labels are resolved via the `useTranslation` hook or the `translate()` helper.

2. **Domain-Specific Namespaces**:
   - Dictionaries are split into 6 focused namespaces to prevent merge conflicts and monolithic file sizes:
     - `common.json`: Global navigation (back, close), loading states, confirmation buttons.
     - `landing.json`: Home screen hero copy, QR scanner prompts, store selection strings.
     - `menu.json`: Categories, search, product card badges, option details, cart, staff call.
     - `orderFlow.json`: Dine-in vs takeout selection, table selection grid.
     - `settings.json`: Display, theme, font scale, accessibility toggles, order history.
     - `setup.json`: First-time accessibility onboarding wizard copy.

3. **Compile-Time Type Safety**:
   - TypeScript recursive template literal types (`I18nKey`) ensure dot-notation keys (e.g. `"staffCall.options.wipes"`) provide full IDE autocomplete and compile-time validation.

4. **Graceful Fallback**:
   - If a translation key is missing in a secondary locale (e.g. `en`), the engine automatically falls back to the base locale (`ko`).

5. **Screen Reader & HTML `lang` Synchronization**:
   - Switching the language automatically updates `document.documentElement.lang`, signaling mobile screen readers (VoiceOver, TalkBack) to load the appropriate vocal engine.

## 3. Usage in Components

### 3.1. Standard Hook Usage with Namespace

```tsx
import { useTranslation } from "@/lib/i18n";

export function ExampleComponent() {
  const { t, language } = useTranslation("menu");

  return (
    <button aria-label={t("staffCall.callAria")}>
      {t("staffCall.button")}
    </button>
  );
}
```

### 3.2. Parameter Interpolation

```tsx
// In locale JSON: "toastSuccess": "{table}번 테이블로 직원을 호출했어요."
const message = t("staffCall.toastSuccess", { table: 3 });
// Result: "3번 테이블로 직원을 호출했어요."
```

### 3.3. Direct Translation Helper (Outside Components / SSR)

```tsx
import { translate, DEFAULT_LOCALE } from "@/lib/i18n";

const loadingText = translate(DEFAULT_LOCALE, "common.loading");
```

## 4. Key Parity Verification (`bun run i18n:check`)

Run the automated parity verification script whenever adding or updating translation keys:

```bash
bun run i18n:check
```

This script traverses every namespace in `lib/i18n/locales/ko` and verifies that every corresponding key exists with an identical schema structure in `en`. If any key is missing or extraneous, the script exits with an error code, preventing CI regressions.
