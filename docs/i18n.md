# Internationalization (i18n) Architecture & Extension Guide

이 문서는 Jumun 플랫폼의 국제화(i18n) 아키텍처, JSON 기반 다국어 딕셔너리 관리 원칙, 새로운 언어 추가 방법, 유지보수 및 CI 검증 로직을 설명합니다.

---

## 1. 핵심 철학 및 설계 원칙

1. **컴포넌트 내 하드코딩 금지 (No Inline Branching)**
   - UI 컴포넌트 내부에서 `if (language === 'ko') ...` 형태의 조건부 분기 코드를 엄격히 금지합니다.
   - 모든 사용자 노출 텍스트, 설명문, 접근성 레이블(`aria-label`), 폼 레이블(`htmlFor`)은 JSON 딕셔너리로부터 `useTranslation` 훅을 통해 로드됩니다.

2. **네임스페이스 기반의 모듈형 JSON 딕셔너리**
   - 도메인/기능 단위로 네임스페이스를 분리하여 대규모 확장 시에도 파일 크기와 충돌을 방지합니다.
     - `settings.json`: 설정 페이지, 화면/테마, 접근성 모드, 결제수단 관리 텍스트
     - `common.json`: 공통 내비게이션(뒤로가기), 로딩 상태, 확인/취소 등 전역 공통 텍스트

3. **타입 안전성 (Compile-Time Type Safety)**
   - TypeScript의 템플릿 리터럴 및 재귀 타입을 활용하여 점 표기법(`"settings.screen.theme.light"`) 키에 대한 완벽한 자동완성과 정적 분석 검사를 제공합니다. 잘못된 키 입력 시 컴파일 단계에서 에러가 발생합니다.

4. **점진적 폴백 (Fallback by Default)**
   - 특정 언어 파일에서 번역 키가 누락되었을 경우, 자동으로 기본 언어(`ko`)의 텍스트로 폴백하여 프로덕션 환경에서 빈 화면이나 텍스트 유실이 발생하지 않습니다.
   - 개발 환경(`NODE_ENV !== 'production'`)에서는 누락된 키에 대해 경고(`console.warn`)를 출력합니다.

5. **접근성 및 표준 웹 준수 (WCAG 3.1 & HTML lang 동기화)**
   - 사용자가 언어를 변경하면 `useAccessibilityStore`와 연동되어 React 리렌더링뿐만 아니라 `document.documentElement.lang` 속성이 실시간으로 동기화됩니다.
   - 스크린 리더(VoiceOver, TalkBack)가 설정된 언어에 맞춰 올바른 음성 엔진으로 낭독합니다.

## 3. 컴포넌트에서 번역 훅 사용법

### 3.1. 기본 사용 (전체 키)
```tsx
import { useTranslation } from "@/lib/i18n";

export function ExampleComponent() {
  const { t } = useTranslation();

  return <h1>{t("settings.title")}</h1>;
}
```

### 3.2. 네임스페이스 스코프 사용 (권장)
네임스페이스를 지정하면 접두사를 생략하고 짧은 키로 작성할 수 있습니다.
```tsx
import { useTranslation } from "@/lib/i18n";

export function FontScaleSelector() {
  const { t } = useTranslation("settings");

  return (
    <div>
      <span>{t("screen.fontScale.title")}</span>
      <p>{t("screen.fontScale.desc")}</p>
    </div>
  );
}
```

### 3.3. 동적 파라미터 보간 (Interpolation)
템플릿 내 `{param}` 토큰을 지원합니다.
```json
// locales/ko/cart.json: { "summary": "총 {count}개 선택됨" }
// locales/en/cart.json: { "summary": "{count} items selected" }
```
```tsx
const text = t("cart.summary", { count: 3 });
// ko -> "총 3개 선택됨"
// en -> "3 items selected"
```

### 3.4. 비-React 유틸리티 및 정적 컨텍스트
React 컴포넌트 밖(서비스, 미들웨어 등)에서는 순수 함수 `translate` 또는 `t`를 직접 호출할 수 있습니다.
```tsx
import { t, translate } from "@/lib/i18n";

// 기본 언어(ko)로 번역
const label = t("common.back");

// 특정 언어로 번역
const englishLabel = translate("en", "common.back");
```

## 4. 새로운 언어 추가 방법 (4단계 가이드)

새로운 언어(예: 일본어 `ja`, 중국어 간체 `zh`, 스페인어 `es`)를 추가할 때는 다음 단계를 따릅니다.

### 1단계: 언어 코드 타입 등록
[`lib/types/accessibility.ts`](file:///Users/rlagkstjr/Desktop/Coding/jumun/lib/types/accessibility.ts)의 `AppLanguage` 유니온에 언어 코드를 추가합니다.

```typescript
// lib/types/accessibility.ts
export type AppLanguage = "ko" | "en" | "ja";
```

### 2단계: JSON 딕셔너리 생성
`lib/i18n/locales/` 디렉토리에 새 언어 폴더를 만들고 기존 `ko` 폴더의 JSON 파일들을 복사한 후 번역합니다.

```bash
mkdir lib/i18n/locales/ja
cp lib/i18n/locales/ko/*.json lib/i18n/locales/ja/
```

- `lib/i18n/locales/ja/common.json`
- `lib/i18n/locales/ja/settings.json`

> **중요**: 키 계층 구조는 반드시 `ko` 파일과 100% 동일해야 합니다.

### 3단계: 딕셔너리 및 지원 언어 목록 등록
[`lib/i18n/index.ts`](file:///Users/rlagkstjr/Desktop/Coding/jumun/lib/i18n/index.ts)에 새로 만든 JSON 파일들을 import하고 `SUPPORTED_LOCALES` 및 `DICTIONARIES`에 등록합니다.

```typescript
// lib/i18n/index.ts
import jaCommon from "./locales/ja/common.json";
import jaSettings from "./locales/ja/settings.json";

export const SUPPORTED_LOCALES: readonly LocaleInfo[] = [
  { code: "ko", name: "한국어", nativeName: "한국어" },
  { code: "en", name: "English", nativeName: "English" },
  { code: "ja", name: "Japanese", nativeName: "日本語" },
] as const;

export const DICTIONARIES: Record<Locale, TranslationSchema> = {
  ko: { common: koCommon, settings: koSettings },
  en: { common: enCommon, settings: enSettings },
  ja: { common: jaCommon, settings: jaSettings },
};
```

> **규칙**: `nativeName`에는 반드시 해당 언어 사용자가 직관적으로 인식할 수 있는 자국어 표기를 기재합니다 (예: "日本語", "中文", "Español").

### 4단계: 무결성 검증 및 테스트 실행
터미널에서 검증 명령어를 실행하여 누락된 키나 오탈자가 없는지 확인합니다.

```bash
npm run i18n:check
npm test
```

모든 검사가 패스하면 언어 설정 메뉴에 새 언어가 자동으로 표시되고 동작합니다.

## 5. 유지보수 및 CI 무결성 자동화

국제화 시스템이 지속 가능하려면 개발자가 새 기능을 추가할 때 모든 언어 파일의 동기화 상태가 강제되어야 합니다.

### 5.1. CLI 검사 도구 (`npm run i18n:check`)
[`scripts/check-i18n.ts`](file:///Users/rlagkstjr/Desktop/Coding/jumun/scripts/check-i18n.ts)는 기준 언어(`ko`) 대비 모든 언어의 키를 재귀적으로 비교하여:
- 기준 언어에는 있지만 타 언어에 누락된 키 (`missingKeys`)
- 기준 언어에 없는 잉여 키 (`extraKeys`)
- 파라미터 보간 토큰 불일치 (예: `ko`에는 `{count}`가 있는데 타 언어에는 누락된 경우)
를 검사합니다. 불일치가 존재하면 Exit code 1로 실패하여 CI 파이프라인(GitHub Actions 등)을 차단합니다.

```bash
npm run i18n:check
```

### 5.2. 단위 테스트 연동 (`tests/unit/i18n.test.ts`)
Vitest 테스트 스위트 내에 `validateAllLocales()` 검증 테스트가 포함되어 있어, 일반 테스트 실행(`npm test`) 시에도 i18n 무결성이 항상 함께 보장됩니다.

## 6. Toss 디자인 시스템 & 다국어 UI 가이드라인

토스 디자인 시스템(TDS)과 바리어프리 UX 원칙을 다국어 화면에서도 유지하기 위해 다음 규칙을 준수해야 합니다.

1. **서체 두께 하한선 500 준수 (Weight Floor >= 500)**
   - TDS 원칙에 따라 영문 및 다국어 텍스트에서도 본문 텍스트는 결코 `font-normal`(400) 이하로 내려가지 않습니다. 기본 본문은 `font-medium`(500), 타이틀 및 컨트롤은 `font-bold`(700)를 적용합니다.
   - 영문 전용 폰트(Toss Product Sans / Inter fallback)와 국문 폰트(Pretendard Variable)가 조화롭게 렌더링됩니다.

2. **텍스트 줄바꿈 및 오버플로우 방지**
   - 영문 및 유럽권 언어는 한국어에 비해 글자 수가 약 20%~40% 길어집니다.
   - 고정된 `w-[100px]` 대신 반응형 `min-h-[44px]` 터치 영역과 유연한 패딩(`px-4`, `py-3`)을 사용하여 텍스트 잘림 현상을 방지합니다.
   - 한국어는 의미 단위 줄바꿈을 위해 `break-keep`을 적용하고, 긴 영단어는 `break-words`로 레이아웃 파괴를 예방합니다.

3. **고대비 및 접근성 검사**
   - 언어가 변경되어도 텍스트-배경 간의 대비비(WCAG AAA 기준 7:1 이상, 고대비 모드 17:1 이상)는 완벽히 유지됩니다.
   - `vitest-axe` 자동화 테스트를 통해 국문/영문 모든 상태에서 a11y 위반 사항 0건을 유지합니다.
